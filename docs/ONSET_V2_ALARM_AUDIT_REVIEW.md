# 경보 민감도 검증 후 판단
실행 37591211784 / 결과 커밋 69c0086edd50c28c59b095a4d197e3c6260fbfdf. 코드/사전 계획을 먼저 커밋한 뒤 실행했다. 기존 v2를 보존했으며 신규 배포 기준을 선택하지 않았다.

## 1. 확인된 개선 여지
7월 재사용 진단에서 기존 과거 오경보 목표5% 기준은 TP102/FP35/FN1이었다. 사전 지정한 목표1% 기준에서는 TP95/FP13/FN8, 재현율92.23%, 정밀도87.96%, 실제 정상 오경보율2.78%다.
오경보를 35회에서13회로 줄이면 놓치는 진입은1회에서8회로 늘어난다. 이는 동일한 모델의 기준 변경 효과이며 재학습에 의한 성능 개선이 아니다.
같은 7월의 전주 기준 목표10%에서는 TP89/FP17/FN14였다. 이 두 사전 지정 후보의 관측 결과를 비교하면 LightGBM 쪽이 더 많이 잡고 덜 오경보했다. 다만 과거 목표는 서로 다르고 이 후보쌍은 결과를 본 뒤 설명용으로 비교했으므로 실제 오경보를 정확히 같게 맞춘 사전 검증 또는 최종 기준 선정이라고 표현하지 않는다.

| 7월 | 99.0% | 7.48% | 97.1% | 89.3% / 35.0% |

사후 진단 열은 각 월 정답을 보고 점수 순위의 분리 능력을 읽은 것이며 배포 가능한 임계값 성과가 아니다.
4월에는 오경보 부담을 같게 제한하면 단순 기준보다도 못한다. 경보 기준 조정만으로 4월이 해결된다고 할 수 없다.
5월에는 점수 분리 능력에 비해 실제 경보 기준이 놓치는 구간이 있어 보정 변화가 후속 검증 후보다.
6월의 거의 완벽한 순위 성능도 반복 곡선과 자료 구성의 영향을 배제하지 못한다.

## 3. 오류 조건
기존 목표5% 기준에서 현재 전력이 고부하 기준의90~100%인 정상 구간의 오경보율은4월72.3%(47/65), 5월24.2%(16/66), 7월59.1%(13/22)다.
기준 근처에 있다는 이유만으로 이후 진입을 과하게 경보하는 조건이 보인다. 이는 관측 오류 연관이며 원인 규명은 아니다. 7월 해당 정상 표본22개라는 작은 분모도 함께 표기한다.
생산량과 기온은 조건별 진단만 했고 F0의 입력을 추가하지 않았다. 기온30초과 표본은7월30회 중 양성14회로 적다.
현재 전력값만 기준은7월 AP0.560이며 LightGBM0.930보다 낮다. 따라서 이 자료에서 단순히 현재 전력의 높이만 읽는 모델과 같은 결과는 아니지만, 범용 제조공정 원리를 배웠다는 뜻도 아니다.

## 4. 시각화 검토
operational_tradeoffs.png를 직접 렌더링해 확인했다. 한글 정상, 두 패널의 제목/축/눈금 겹침 없음, 네 후보 범례는 하단 바깥에 있다.
각 점은 과거 보정에서 정한 기준의 실제 결과이며 이어진 선은 중간 기준의 검증 결과를 뜻하지 않는다. 이 그림을 평가 정답으로 최적화한 ROC 곡선이라고 부르지 않는다.

## 5. 다음 한 단계
모델 선택을 유지한 채 월별 경보 보정 불안정을 먼저 검증한다. 후보: 월1회 고정과 매7일 갱신, 동일한 과거14일의 확정된2시간 정답 사용. 평가 시점 뒤의 정답은 금지하고 준비시간은 도입하지 않는다.
새 실험 전에 갱신 일정·고정 목표·성공 기준을 별도 계획에 기록한다. 4월의 점수 분리 한계는 이 방법으로 해결됐다고 선결론 내리지 않는다. 기준을 정하는 문제와 점수 자체의 성능을 계속 분리한다.
최종 제출에는 전력값 회귀, 고부하/오류 조건, 조건부 피크 저감 결과를 함께 제시해야 한다. 진입 분류 결과나 오경보 감소만으로 실제 절감액을 보장하지 않는다.
