# 연구 목표와 단계별 프로세스

## 최종 목표
제공된 제조 생산·전력 데이터로 전날 16시에 다음 날 96개 15분 구간의 전력을 예측한다. 예측오차와 피크 조건을 분석하고, 조정 가능한 부하가 실제로 존재한다는 가정 아래 30~60분 이동 시나리오를 계산해 한전 요금과 추가 노동비를 함께 고려한 의사결정 기준을 제시한다.

## 연구 우선순위
대회의 본체는 아래 세 가지이며, 모두 제공 데이터만으로 먼저 완결한다.

1. 향후 지정 시간구간의 전력사용량 예측과 단순 기준모델 대비 검증
2. 예측오차가 커지는 생산·시간 조건과 최대피크 발생 조건 분석
3. 생산일정 또는 설비가동 시점 조정을 가정한 피크 저감안과 한계 검증

요금·인건비 분석은 위 결과를 현장의 의사결정 단위인 원화와 실행 여부로 번역하는 부가 차별점이다. 외부 정책자료는 예측모델의 학습·특징선택·성능평가에 넣지 않는다. 따라서 보고서와 발표의 약 80~85%는 데이터, 모델, 오류·피크 요인, 피크 저감 실험에 배정하고 경제성은 약 15~20%로 제한한다. 분량은 최종 양식에 맞춰 조정하되 이 우선순위는 바꾸지 않는다.

연구의 전체 연결은 다음과 같다.

`데이터 신뢰성 → 시점 누수 없는 예측 → 실패·피크 조건 → 실행 가능한 부하 이동 → 요금·노동비 순이익`

## 단계와 체크포인트

| 체크포인트 | 단계 | 핵심 질문 | 완료 조건 | 현재 상태 |
|---|---|---|---|---|
| CP00 | 문제 정의·환경 | 언제 무엇을 예측하고 누가 어떤 결정을 내리는가? | 예측시점·대상·가정·평가지표 고정 | 완료 |
| CP01 | 데이터 감사 | 시간·결측·중복·단위가 믿을 만한가? | 원본 해시, 시간축 변환, 오류·결측 표 | 완료 |
| CP02 | 예측 실험 | 단순 기준보다 안정적으로 나은가? | 시간 분할, feature ablation, 모델 비교, 고정 선택 | 1차 완료 |
| CP03 | 오류·피크·민감도 | 언제 실패하고 전처리에 얼마나 흔들리는가? | 조건별 오류, 결측·극단값 시험, 중요도, 불확실성 | 1차 완료 |
| CP03B | 출제요구 완결 점검 | 세 요구사항의 증거가 보고서 본문을 독립적으로 구성하는가? | 지표·요인·실패조건·해석 한계·필수 그림의 누락 점검 및 보강 목록 | 다음 단계 |
| CP04A | 피크 저감 운영실험 | 예측을 사용한 제한적 이동이 실제 피크를 얼마나 낮추는가? | 동일 제약의 무조정·기준·AI·oracle 비교, 피크·반동·오판 지표 | 미착수 |
| CP04B | 정책·경제성 번역 | 검증된 저감 결과가 어떤 계약·노동 조건에서 이득인가? | 외부자료 대장, 요금·노동비 근거, 순편익·손익분기 민감도 | 노동비 근거만 완료 |
| CP05 | 보고서·발표 | 평가자가 재현하고 의사결정을 이해할 수 있는가? | 실행 notebook, 보고서, 발표, 제출물 검사 | 미착수 |

## 보고서 본문 비중 가이드

| 내용 | 권장 비중 | 심사자가 확인할 핵심 증거 |
|---|---:|---|
| 문제정의·데이터 신뢰성·전처리 | 15% | 예측 시점, 데이터 범위, 결측·시간오류·중복, 적용 한계 |
| 특징공학·모델 비교·검증설계 | 30% | 시간 누수 방지, 기준모델, ablation, 검증/테스트 분리, 선택 규칙 |
| 예측오류·피크 조건·불확실성 | 20% | 큰 오류 조건, 미탐·오경보, 중요도와 인과의 구분, 민감도 |
| 피크 저감 운영실험 | 20% | 같은 제약 아래 비교, 실제값 평가, 반동피크·실패사례·현장 제약 |
| 요금·노동비 의사결정 | 15% | 공식 출처, 계약별 조건부 효과, 순편익과 실행하지 않을 조건 |

산업 전문가는 실행 가능성과 비용·오경보를, 학계 전문가는 누수 없는 검증과 비교의 공정성을, 연구기관 전문가는 재현성·공통 적용범위·정책 근거를 확인할 가능성이 높다. 각 관점에 별도 과장을 하지 않고 같은 실험 증거가 세 관점을 모두 만족하도록 구성한다.

## 단계별 GitHub 체크포인트 규칙
1. 각 단계 시작 전 `PROJECT_STATUS.md`에서 입력·출력·완료 기준을 확인한다.
2. 코드는 작은 단위로 실행하고 결과는 `outputs/`, 그림은 `figures/`, 판단 근거는 `docs/`에 저장한다.
3. 단계 완료 시 `python run_stage.py check`와 해당 단계 실행을 통과시킨다.
4. `PROJECT_STATUS.md`와 `HANDOFF.md`에 결과, 한계, 다음 명령을 갱신한다.
5. 다음 형식으로 커밋하고 즉시 push한다.

```bash
git add .
git commit -m "CPXX: summarize completed checkpoint"
git tag -a cpXX -m "Completed checkpoint summary"
git push origin main --follow-tags
```

6. 단계 중간에 30분 이상 재현하기 어려운 계산이 끝났거나 작업을 중단할 때도 `WIP:` 커밋으로 push한다. `HANDOFF.md`에 마지막 성공 명령과 다음 명령을 기록한다.
7. 테스트 결과를 본 뒤 모델·전처리를 바꾸는 후속 실험은 `experiments/<이름>` 브랜치에서 진행하고 기존 CP02 결과를 덮어쓰지 않는다.
8. 공개 저장소이므로 비밀번호·토큰·개인정보를 커밋하지 않는다. 원본 데이터 재배포 조건이 확인되지 않았다는 사실을 README에 계속 표시한다.

## 연구적으로 지켜야 할 경계
- 실제 미래 생산계획인지 불명확한 열을 예측 입력으로 사용하지 않는다. 실제 미래값을 사용한 결과는 oracle로 분리한다.
- 평균오차가 좋아도 피크 탐지가 나빠질 수 있으므로 두 지표를 같이 보고한다.
- 전력량 보존은 생산량 보존을 증명하지 않는다. 설비별 이동 가능 정보가 없어 경제성은 조건부 시뮬레이션이다.
- 역사 최대수요에 묶이면 최대전력 감소가 기본요금 절감으로 이어지지 않을 수 있다.
- 유리한 요금·인건비·기간만 골라 확정 절감액처럼 제시하지 않는다.
- 외부자료를 사용하면 `docs/EXTERNAL_DATA_REGISTER.md`에 활용 사유·방법·출처·확인일·공개 가능성·영향 범위를 먼저 기록한다.
- 외부 정책자료는 비용 후처리와 시나리오 정의에만 사용하며, 대회 제공 데이터의 예측 성능을 높인 것으로 표현하지 않는다.
